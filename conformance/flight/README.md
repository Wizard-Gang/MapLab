# Owned free-space flight corpus — CC0-1.0

These are original MapLab project fixtures, dedicated to CC0-1.0. `sources/` copies our owned placeholder closure. Every case supplies its own small map/profile; forest-patrol additionally checks the unchanged owned forest fixture. No borrowed assets, music, engine code or schemas. `index.json` hashes all final fixture bytes except itself.

## Scope and identities

The existing `maplab.reference-controller@1` source profile now has a separately identified reference flight subset: `maplab.reference-flight@1`, with a final motor source digest and the existing collision implementation digest. Ground controller and surface/airborne graphs remain unchanged. Proofs have `canCertify:false`, `complete:false`: verified means the entire native-flight reference input replays under the recorded static assumptions, not engine AI parity, arbitrary mode changes, or global reachability. Failure is no route within the declared lattice/replay budget, never universal physical unreachability.

Only static rectangular hover/fly actors with one fly ability are supported. Other capabilities, non-hover motion, unsupported controller/collision contracts, moving compatible colliders, relevant nav overrides/links, and launch/modifier intent report unsupported. Geometry is limited to128 body shapes/1024 vertices,256 supports and64 mode bindings; matching flight volumes must be rectangles. Collision uses physical bodies with reciprocal category/mask filtering and the existing exact finite-rectangle axis sweep. Authored one-way supports are conservatively treated as two-sided flight barriers, including slopes; no directional crossing or landing/mode transition is inferred. Art never supplies obstacles.

Matching `modeVolumes` bind by fly mode AND selected profile ID; their rectangle union must contain the entire body and each axis sweep. With no matching bindings, the world bounds are the permitted volume. Adjacent volumes may jointly contain a straddling body. A gap, even1/16 WU, cannot be crossed. World bounds always apply. Body coordinates use center X/foot Y, integers in1/256 WU; velocities are integer su/tick at60 Hz.

## Motor and search rules

Input is a run-length sequence of desired velocity `{fromTick,targetVx,targetVy}`. The v1 motor uses conservative L1 (axis-summed) speed and velocity-delta bounds; these also bound Euclidean speed/acceleration. Coefficients are positive integers≤8192. Target velocities must fit the speed budget. Velocity approaches target by proportionally truncating each component toward zero within acceleration. If a nonzero old velocity changes direction or reverses, the delta budget is min(acceleration,turnAcceleration). If both truncations vanish, take one legal unit toward target, decreasing-magnitude axes first then X. If rounding would exceed the L1 speed cap, remove excess from increased-magnitude components, X first. This deterministic integer rule does not model a universal aircraft turn radius.

Each tick sweeps X then Y, with the new velocity, checking the full finite rectangle throughout both segments. Penetration is rejected; exact tangency is allowed. A blocked/unsupported tick returns the old state unchanged. A native query first brakes its actual velocity to rest through that motor; an unsafe braking path fails, without teleporting or borrowing a ground-mode transition.

The planner builds a separate cardinal free-space lattice over the matching volume union's AABB, clipped to world bounds. Each axis includes its boundaries, a regular grid and exact source/goal coordinates. Neighbor edges accelerate/brake rest-to-rest through the same motor, using the maximum speed for which `v + stoppingDistance(v) ≤ remainingDistance`; stopping distance sums the future deceleration velocities. Turns therefore stop before changing direction. This conservative hover planner is not a generalized kinodynamic optimizer. Motion templates are chained and replayed again from the actual preceding state before publication. A* uses ceil(Manhattan distance/speed); Dijkstra uses zero. Costs include every movement, braking and authored wait tick. Limits cover grid size, aggregate expansions, per-edge ticks, total replay work, route ticks and waypoint count; cancellation yields no partial proof.

A patrol uses the entity's own profile, explicit waypoints/waits, and all legs of once/loop/ping-pong routes. Cyclic patrols currently require the actor at the first waypoint; no staging/mode-entry action is invented. Route conditions and unavailable required abilities are unsupported. The selected invalid-route/fallback intent is reported as configured, not executed. Static world/profile/motor/settings/query hashes bind every proof; source/profile edits and cancellation immediately hide old worker results. Art-only changes preserve physical cache identity. No source/history changes occur during query or replay.

## Cases and independent proof

Cases cover forest `region.flight`/`route.flyer`, an obstacle detour, narrow fit and oversized collider refusal, a thin full-height wall, adjacent-volume union and tiny-gap refusal, body outside volume, unmatched-profile world fallback, reciprocal mask filtering, unsafe initial braking and a complete closed obstacle patrol. `turn.input.json` records a moving90-degree turn followed by braking; the horizontal momentum persists under the turn cap. Each expected file records complete integer states, RLE input, profile/controller/world/settings/query digests, legs and full swept dependencies.

`tests/consumer/flight.mjs` is a standalone Node standard-library final-byte reader. It checks fixture hashes, profile and implementation identity, independently replays integer motor equations, checks all states and axis-swept rectangles against the volume union and physical obstacle rectangles (and conservative polygon/support AABBs for the forest flight, which stays disjoint), verifies waits/closure and proof hashes. This oracle is qualified to the owned corpus, not arbitrary polygon collision. Tests coherently rehash forged velocity/position traces and still require semantic rejection. Node/browser parity, A*/Dijkstra costs, ground-graph separation, unsupported states, masks, cancellation/stale replies and editor read-only behavior are checked separately.
