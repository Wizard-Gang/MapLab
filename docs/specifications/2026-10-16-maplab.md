# MapLab: architecture and controlled implementation specification

Planning baseline: **16 October 2026, America/New_York**. Status: proposed architecture, not an implemented product or an approved repository change. Target repository: `Wizard-Gang/MapLab`. This pass produced planning material only; it did not create or change repositories, application code, branches, settings, releases, or PRs. No visual mockups were generated.

**Revision R1 (adopted at ML-003, 17 October 2026):** the owner-approved [R1 revision](2026-10-17-maplab-r1/README.md) amended the bodies of C3, C4, D1–D4, F1–F5, G2, H1, H4, I1 and I2, the matching E5 time unit and the ML-009 J2 row in place; each amended section opens with an R1 note. Headings, reserved IDs and order are unchanged. Research and decision sections A, B and K keep their 16 October text; R1's own A, B and K files record the updated research, including the reversed storage recommendation (library folder through a loopback plugin, not IndexedDB-first).

**Recommendation:** build a standalone React/TypeScript/Vite authoring application around an engine-independent world contract, explicit footholds and collision bodies, a versioned reference movement controller, and rebuildable capability-specific navigation. Use Canvas 2D for bulk artwork and overlays, React/DOM for controls, and workers for navigation and expensive validation. Optional RigLab imports supply presentation only. MapLab owns authored world data; the engine owns live physics, AI, combat, progression, and mutable world state.

Normative words **must**, **should**, and **may** describe the proposed MapLab contract. **Verified** describes inspected source behavior. **Proposed** describes a MapLab choice. **Deferred** means implementation may wait, while the specified source-data boundary must already exist. The TypeScript and JSON below are design material, not application implementation.

These are comparisons of documented capabilities, not claims of equivalent file formats or physical behavior. MapLab remains orthogonal, side-view, X-right/Y-down throughout.

### A3. MapleStory evidence and generalization

Public community implementations expose MapleStory-style map records with foothold IDs, endpoint coordinates, predecessor/successor links, ladder/rope geometry, portals, objects and backgrounds. They are evidence of the inspected implementations and reverse-engineered data conventions, **not an official Nexon specification or proof of the current commercial client**. No copyrighted map/art dataset is a required dependency. Source details and limits are recorded in the source ledger at the end of this document.

Generalize the useful model: explicit support segments with stable identity and optional adjacency; separate climbing geometry; portals as explicit targets; visual layers separate from support. Do not carry forward numeric foothold trees, WZ nesting, hard-coded IDs, commercial physics constants or assumptions that a linked neighbor is always traversable. Coincident endpoints establish geometry; profile-specific feasibility establishes navigation.

### A4. Platformer navigation research

[Surfacer](https://github.com/snoringcatgames/surfacer/tree/241c43cca59f8cd9414cf89cbdcc9925f3fcdc85) is a genuine platformer navigation implementation with surface parsing, generated movement edges, graph search and character execution. Its author's [explanation of graph construction](https://devlog.levi.dev/2021/09/building-platformer-ai-part-4-platform.html) supports the approach but also documents approximations. Its Godot 3 implementation is useful research, not a library MapLab should embed or a completeness proof.

**Proposed:** retain support intervals as coarse spatial structure, then attach stateful action witnesses: launch range/pose, initial motion, input schedule, collision sweeps and landing conditions. Finite sampling can miss legal routes. A found route must be replayed against the selected reference controller; a failed sample search must not be labeled universally impossible. A* or Dijkstra operates on this graph, not directly on artwork cells. Sections E and I specify how to test that claim.

### A5. Camera, browser storage and reproducibility

[Godot Camera2D](https://docs.godotengine.org/en/stable/classes/class_camera2d.html) documents drag margins, bounds and smoothing; its actual screen position can differ from the target node. [Cinemachine Position Composer](https://docs.unity3d.com/Packages/com.unity.cinemachine@3.1/manual/CinemachinePositionComposer.html) documents per-axis damping, screen composition and lookahead, including noise sensitivity. MapLab should declare camera intent and preview a documented model. Vertical grounding hysteresis and landing lookahead below are proposed policies, not promised built-in behavior of either engine.

The [File System Standard](https://fs.spec.whatwg.org/) defines handle-based access and origin-private storage; the [File System Access specification](https://wicg.github.io/file-system-access/) describes user-selected file access. [Writable streams](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable) commit changes on close; that is not a multi-file transaction. [OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) is quota-limited and can be lost with site storage. Use portable file import/download plus transactional IndexedDB recovery as the baseline, with optional picker/OPFS adapters after feature detection.

[RFC 8785 JCS](https://www.rfc-editor.org/rfc/rfc8785.html) provides canonical JSON property and number serialization; it does not order semantically unordered arrays or canonicalize ZIP files. [JSON Schema 2020-12](https://json-schema.org/draft/2020-12) supports closed composition. MapLab must separately specify array ordering, path safety, byte hashing and archive metadata. A SHA-256 manifest proves byte integrity against that manifest; publisher authenticity requires an independently trusted digest/signature and is outside the default local workflow.

## C. MapLab product specification

### C1. Document workflow and layout

The product opens to a project/library browser with independent map documents, reusable tilesets, prefabs, palettes, movement profiles and optional presentation packages. New map asks for name, bounded world rectangle, logical tile size and default movement profile. Opening validates into a staging model before replacing the active document. Invalid files open a diagnostic/read-only recovery view. Save writes authored data; Export creates a dependency-closed consumer bundle. Save As creates a new file identity only if the user chooses “duplicate map”; a relocated save retains map identity.

Use RigLab's toolbar/viewport/inspector structure as the initial reference. Left: layer/object hierarchy and asset browser. Center: viewport and active tool. Right: selection properties. Bottom: diagnostics/navigation/test details. Panels can collapse without changing world data. This describes behavior, not a mockup.

Selection supports click, marquee, shift-toggle, hierarchy search, overlap cycling, layer filters, locked-object exclusion and select-through. Object handles stay CSS-sized while geometry remains world-sized. Inspector numeric entry supports fractional units and explicit snap controls; text inputs suppress destructive global shortcuts. Dragging previews a transaction; release commits once; Escape restores it. Delete reports affected references and offers cancel, retarget or explicit cascade. No silent route/portal retargeting.

New/Open/Save/Save As, per-document undo/redo, rename, duplicate, copy/paste, object search, zoom-to-selection, fit-bounds, map resize, dirty state and library operations are shared. Default shortcuts: platform Cmd/Ctrl+N/O/S/Shift+S, Z/Shift+Z, C/V/D, Delete/Backspace, Escape; Space+drag pans, wheel pans and modifier+wheel zooms at cursor. Tool letters are configurable and focus-aware. Keyboard-accessible hierarchy and numeric operations are required even before full non-pointer painting accessibility.

Copy/paste uses a versioned structured clipboard document, new persistent IDs and a complete internal-reference remap. External references retain identity only when resolvable in the target project; otherwise paste previews diagnostics. Duplicate map remaps local identities and self-portals but preserves explicit links to other maps. Reordering/visibility in the UI does not mutate physical coordinates.

### C3. Visual layers and reusable content

*R1 revision, adopted at ML-003 on 17 October 2026: `actors` layers and actor planes; foreground is decided by order ([R1 D5](2026-10-17-maplab-r1/D-world-physics.md#d5-visual-layers-and-actor-planes-changed)).*

Layers are flat records with parent-group references and an explicit sibling order; group cycles are invalid. Kinds: group, tile, sprite, background and `actors`. An `actors` layer marks where actors paint; a playable map needs at least one, and the first in paint order is the default actor plane. Paint order is the depth-first order of `(parent, order, id)`, and everything after an actors layer paints over the actors in it, so foreground means order, not kind. The former `foreground` kind is removed. Render visibility, opacity and depth are authored presentation data; locks, solo state, selection and snap overrides are editor sidecar data. Physics, traversal, gameplay, camera and navigation overlays have independent toggles. An invisible art layer cannot disable physical collision. Authored “enabled” is a separate field on physical/gameplay objects.

Scenery supports asset-local pivots, raster/SVG sprites, frame animation, grouped objects, buildings and foreground occlusion. Prefabs contain visuals, colliders, footholds, traversal and typed gameplay objects with internal references. First implementation expands instances at placement/export with new IDs; the map's `prefabPlacements` keeps their provenance. Nested prefabs and live overrides are deferred; cycles are always rejected. Optional animated visuals are nonphysical unless an explicit rigid moving-body definition owns both geometry and presentation.

Backgrounds declare per-axis parallax, repeat period and axes, scroll velocity in WU per tick (`scrollWUPerTick`), phase, animation and world/camera space. A camera-relative sky does not become a collision layer. Repetition uses mathematical modulo, including negative coordinates. Foreground occlusion uses render order plus an optional advisory `occlusionFade` alpha that an engine may apply while an actor is behind the layer; it never hides collision from navigation. A grounded actor paints in its support foothold's `planeId` (null means the default actors layer); while airborne or climbing it keeps its last plane, or uses the climb path's `planeId` when one is set.

### C4. Camera and environment behavior

*R1 revision, adopted at ML-003 on 17 October 2026: durations are 60 Hz ticks, and the vertical policies are `platformSnap` and `climbFollow` ([R1 F2](2026-10-17-maplab-r1/F-formats.md#f2-r1-changes-to-the-adopted-field-vocabulary), [`contract/gameplay.ts`](2026-10-17-maplab-r1/contract/gameplay.ts)).*

Map defaults and priority zones declare logical view size, horizontal/vertical follow, dead zone, lookahead limits, damping ticks (`dampingTicks`), bounds, zoom and transition ticks/curve (`transitionTicks`). Camera bounds constrain the **visible rectangle**, not merely the target point. If bounds are smaller than the view, center and letterbox; never oscillate between incompatible clamps. Zone precedence: highest priority, then explicit stable ID tie-break; blend from the previous effective configuration over the declared duration. Equal-priority overlapping zones are warned about. A disabled follow axis centers that axis on its effective bounds; thus locked zones have a deterministic center without a separate target. `deadZone` uses normalized left/top/width/height inside [0,1]; effective view size is `viewWU / zoom`.

Recommended reference preview: follow X with bounded velocity lookahead; keep Y near the supporting surface during short jumps, follow when the upper safety margin is exceeded, and anticipate long falls with capped downward lookahead. `verticalPolicy` is `continuous`, `platformSnap` or `locked`. `platformSnap`, the former grounded hysteresis renamed after Keren's platform snapping, holds camera Y on the last support during jumps, snaps when the actor lands higher, and prevents repeated landing/jumping camera snaps. `climbFollow` overrides the vertical hold on climb paths so ladders and ropes remain visible. Landing prediction is advisory and bounded; leaving a camera zone does not move the actor. Portals/checkpoint resets clear camera smoothing; boss arenas use locked bounds/zoom and a declared transition. Implementations must test tall shafts, stacked floors, large jumps and drops. Camera preview and engine implementation have a separate conformance identity.

Audio zones reference tracks/ambience with priority, loop and fade ticks (`fadeTicks`); ambient effects, screen shake and cutscenes reference validated effect IDs. No event JSON executes a shader, script or expression. The engine resolves playback, progression and camera runtime state.

## D. World data and physics specification

### D1. Coordinate and precision contract

*R1 revision, adopted at ML-003 on 17 October 2026: authored quantum 1/16 WU, range ±131,072 WU, integer controller sub-units and 60 Hz tick durations ([R1 D1](2026-10-17-maplab-r1/D-world-physics.md#d1-coordinates-and-precision-changed)).*

| Space | Definition and conversion |
|---|---|
| World | Logical world units (WU), X right, Y down; clockwise-positive degrees for visual rotation. Negative coordinates permitted. Default tile = 32 WU; default artwork density = 1 pixel/WU, explicitly configurable. Neither defines physics scale. |
| Screen | CSS pixels relative to viewport content rectangle. `screen = viewportOrigin + zoom * pixelsPerWU * (world - cameraOrigin)`. Inverse uses the same transform. Device pixel ratio scales the canvas backing store only. |
| Tile | Integer `(column,row)` in a tile layer. World top-left = layer tile origin + cell size × index. Use floor division for negative cell/chunk coordinates; no truncation toward zero. |
| Snap | Independent per-axis spacing and origin, with explicit free-placement mode. Snap first to configured grid, then to serialization quantum. Endpoint/object/pixel snapping are separate affordances with precedence shown in the status bar. |
| Asset local | Raster image pixels or sanitized SVG viewBox units; explicit pivot and WU per asset unit. Visual transform = translate × clockwise rotate × mirror × scale × translate(-pivot). |
| Physical | Geometry in WU; static source geometry is never rounded to screen pixels. A rigid body may own translated local geometry; arbitrary nonuniform scaling/rotation of colliders is prohibited in the initial controller. |
| Actor anchor | Physical actor origin is the bottom-center foot reference, including while airborne; rect local bounds are `[-width/2,-height,width,height]`. The supporting geometric anchor/contact manifold is distinct: slope stance resolves the body above the segment (`fullFootprint`). The ground-contact offset that removes slope hover is presentation-only (G2). Facing is separate from physics position. |
| Controller units | Sub-unit **su = 1/256 WU**; tick = 1/60 s. Controller state is integer su, su/tick and su/tick² ([R1 RC1](2026-10-17-maplab-r1/D-reference-controller.md#rc1-units-and-arithmetic)). |
| Camera/parallax | Editor camera is transient. A parallax world layer renders `(world - origin - factor*(camera-origin))*scale`; factor 1 is world-fixed, 0 camera-fixed. Explicit camera-space layers use view coordinates and no world hit testing. |
| RigLab | Both art/world axes point right/down. Explicit `worldUnitsPerRigUnit` and rig-local `groundAnchor` convert; no implicit Y reflection. Hexframe integration needs an independent Y-up adapter if later requested. |

**v1 numeric rules (R1):** serialize coordinates, lengths, sizes, snap spacings and asset/world translations as exact multiples of **1/16 WU** (`0.0625`, at most four fractional digits); normalized segment parameter `u` as multiples of **1/65536**. Every authored coordinate, including `bounds`, satisfies **|v| ≤ 131,072 WU (2¹⁷)**; sizes must remain inside representable bounds. Store JSON numbers in WU, with quantization declared by the format (`coordinates.quantum: 0.0625`, `ticksPerSecond: 60`). UI displays sufficient precision to round-trip. Rounding is nearest with halfway values away from zero; normalize negative zero to zero. Quantize once when committing edits/importing external coordinates, and reject off-quantum authored inputs unless the explicit import/migration operation shows the conversion. Never repeatedly quantize pointer previews. Visual angles use 1/256 degree; positive scales use a documented 1/65536 quantum. Durations in authored data are integer ticks at the map's declared 60 Hz (waypoint waits, respawn and portal delays, camera blends, frame timings). Controller coefficients are integers in su, su/tick and su/tick²; they are not world-coordinate quantization targets.

Pixel-perfect art alignment means a pivot maps to the configured art pixel grid; it does not move physical bodies or constrain viewport zoom. Decimal snap spacing must be representable on the coordinate quantum; show the effective spacing. With q = 2⁻⁴ and |v| ≤ 2¹⁷, every authored coordinate is `n·2⁻⁴` with |n| ≤ 2²¹ < 2²⁴, so it is exact in IEEE binary32 engines. In su, coordinates are at most 2²⁵, differences at most 2²⁶ and products of two differences at most 2⁵², so every orientation and intersection predicate is exact JavaScript integer arithmetic (≤ 2⁵³) without BigInt. Bigger worlds are multiple maps joined by portals; a `maplab.world` layout document is reserved (F1).

Resize changes bounds only. Cropped content stays at its original coordinates and is reported; trimming/deleting or translating content requires a separate, previewed transaction including anchors, zones and paths. Bounded maps initially; fixed tile chunk coordinates and stable IDs already allow a later streaming index. Streaming boundaries do not redefine world axes or object IDs; activation/simulation ownership across chunks is deferred.

### D2. Physical geometry and authority

*R1 revision, adopted at ML-003 on 17 October 2026: stable `shape.id`, clockwise polygons, support versus blocking faces, rational slope limits, foothold `planeId` and a presentation-only ground-contact offset ([R1 D2](2026-10-17-maplab-r1/D-world-physics.md#d2-physical-authority-kept-with-changed-details), [D3](2026-10-17-maplab-r1/D-world-physics.md#d3-footholds-kept-model-changed-details), [G3](2026-10-17-maplab-r1/G-engine-integration.md#g3-actor-composition-and-riglab-presentation-kept-with-r1-specifics)).*

Collision bodies own rect/segment/simple-polygon shapes, each with a stable `id` that edge references name as `shapeId`, plus enabled state, category/mask, material and optional deterministic motion definitions. Body segments are two-sided solid barriers; one-way behavior belongs only to explicit footholds. Polygons have no self-intersections or holes in v1 and are clockwise on screen (positive signed area in Y-down): edge i runs vᵢ→vᵢ₊₁ with outward normal `(dy,-dx)`, and rect edges are top, right, bottom, left; concave simple polygons are valid source and deterministically decomposed into convex pieces for a controller that needs them. Derived pieces keep a mapping to source collider/edge IDs. Rect/polygon boundaries are closed; strict penetration and contact tolerance are separately defined. Arbitrary collider scale, rotating moving platforms and deformable terrain are deferred capabilities, not silently approximated.

**Footholds are first-class objects.** Each has stable ID, endpoints in its owning body's frame (world frame when owner is null), material, direction, collision mode and named endpoint connections. Require nonzero length and X-monotone left-to-right orientation for support segments; vertical surfaces are walls, not footholds. An upward normal for a segment `(dx,dy)` is normalized `(dy,-dx)` in Y-down. Walkability depends on the movement profile's maximum slope, an exact ratio `{rise, run}`, and body clearance, not just the existence of the segment: a foothold with run `dx` and rise `dy` is walkable iff `|dy|·run ≤ dx·rise`, with no trigonometry. A face is a **support face** (upward-facing and walkable for the profile) or a **blocking face** (a wall, a ceiling, a face too steep for the profile, or a two-sided segment); a non-walkable foothold blocks rather than supports. Each foothold names its actor plane `planeId`; null means the map's default actors layer.

A `surface` anchor names a geometric point on support, not an already collision-resolved body origin. The stance resolver uses the selected finite collider to place the actor's foot reference without penetration. For an upright width-24 rect on slope `dy/dx=-0.5`, its bottom-center must be 6 WU above the line at that X (plus contact skin); placing it directly on the line penetrates the upslope face. Full-footprint support means the projected footprint is covered by the support chain, not that every bottom point simultaneously touches a slope. Across welded seams, use the union of compatible connected support coverage. Capsule stances use their actual shape. Positive `normalOffset` adds outward displacement after stance resolution. Flat surface anchors and foot references coincide apart from declared skin. Actual contact points are reported independently and never inferred from rendered feet. The full-footprint lift reads as hovering, so a presentation-only ground-contact offset (G2) draws the art's feet on the line while the collider stays put. The MapleStory-style `centerFoot` stance stays a declared profile value that controller v1 reports as unsupported.

Solid support footholds reference the exact exposed top edge of a solid collider. That collider owns collision resolution; the foothold supplies identity, material and navigation semantics. Do not resolve that face twice. A one-way foothold is itself a directed support surface and needs no hidden solid volume below it. Walls and ceilings are collider faces and cannot become floors merely because artwork resembles one. Object colliders join the same physical index as terrain colliders. Overlapping same-facing supports with ambiguous ownership are errors; adjacent surfaces and intentional one-way platforms above solids are allowed after separation checks.

Endpoint connectivity is authored source intent, not a generated route. Snap-and-connect is explicit; exact quantized equality and compatible owner frames are required for welded endpoints. Surface transitions still test slope, clearance, material restrictions and direction. Split preserves one existing ID and allocates another; the transaction deterministically remaps surface anchors, connection endpoints and edge references. Join retains a chosen ID only for compatible collinear segments; material/mode/owner mismatch blocks it. Deleting referenced geometry cannot silently drop patrol/start/ladder anchors.

Materials define traction as an integer where 256 = 1.0, conveyor tangent speed in su/tick and a typed hazard/effect reference. Slipperiness changes controller deceleration; hazard damage/resolution belongs to the engine. Collision masks and entity category are explicit; art layers do not supply masks. Directional navigation bans affect route planning; physically one-way traversal needs a declared collision/traversal rule, not merely a navigation arrow.

Moving platforms/elevators own local geometry plus a translation path, tick durations, loop/ping-pong/once mode and initial phase. Engine policy defines rider velocity transfer, crushing and blocking. Initial authored enabled/phase is a starting condition; current phase/rider lists are runtime state. Conveyors specify tangent speed independently of artwork animation. Basic controller support for moving platforms can be deferred while source geometry remains valid and preview reports the unsupported feature.

### D3. Traversal and anchors

*R1 revision, adopted at ML-003 on 17 October 2026: climb paths may carry an actor `planeId`, faces are named by `shapeId`, and durations are ticks; access-point semantics are kept ([R1 D4](2026-10-17-maplab-r1/D-world-physics.md#d4-traversal-and-anchors-kept-with-stance-changed)).*

Anchors are world points, foothold-relative `(footholdId,u,normalOffset)`, collider-local points or entity-local points. Surface references resolve after body transforms; they survive resizing and body translation. Authoring visual grouping does not move physical anchors unless the explicit group-transform transaction includes their owners. Cached resolved anchor positions never replace source references.

Ladders/ropes define a climb polyline (vertical in v1), grab radius, allowed direction, ability tags, an optional actor plane `planeId` and access points. Each access point names a polyline parameter, actor anchor, entry mode (grounded/airborne/either), exit mode and required conditions. A bottom rope point may intentionally be airborne; validate its grab region rather than demanding a floor. Grounded entries require support and clearance; grounded exits require usable landing space. Intermediate ladder exits are explicit. Ropes are initially kinematic climb paths; physical swinging is a separately declared ability/solver, never inferred from a rope sprite.

Walls/ledges/grapple anchors reference physical faces by `{bodyId, shapeId, edgeIndex}`, local grip points, normal/approach region and permitted abilities. Swim/flight/launch zones are typed regions; movement modifiers refer to versioned definitions, start/end conditions and stacking policy. Portals/doors name a stable destination map and destination start/portal entity; no destination filename or array index. Scripted traversal is a registered traversal action with typed parameters and geometry; the editor marks it unresolved if it has no supported solver. It does not execute arbitrary code.

Wall/ledge/grapple points use the referenced body's local frame; approach regions are world-space. Typed launch zones declare an impulse in controller velocity units (su/tick), a gameplay-role filter and `cooldownTicks`; the selected profile's launch capability/policy must permit it. Validate climb path degeneracy, entry/exit attachment, reach/clearance, unsupported ability assumptions, cycles in references, one-way transitions and cross-map targets. Reachability diagnostics always name profile and controller. A decorative ladder with no traversal geometry never creates a route.

### D4. Movement contract and runtime separation

*R1 revision, adopted at ML-003 on 17 October 2026: profiles are integer ([R1 RC5](2026-10-17-maplab-r1/D-reference-controller.md#rc5-movement-profile-maplabmovement-v1-changed)).*

Four separate concepts must remain separate: world collision geometry; controller/physics semantics; movement capability profile; live actor state. A profile contains collider shape/dimensions, mass-independent kinematic acceleration/speeds, braking, gravity/fall cap, ground jump impulse and hold/release behavior, maximum extra airborne jumps, air control, dash definitions, wall/ledge/climb permissions, swimming/flying, grapple/swing/teleport support, surface restrictions and ability tags. Knockback/launch and temporary modifiers have typed capability entries and policy references. RigLab animation has none of this authority.

Kinematic values are integers in controller units: speeds in su/tick, accelerations in su/tick² and durations in ticks at 60 Hz, while collider geometry stays in WU on the D1 quantum. `maxSlope {rise, run}` and `uphill`/`downhill` ratios replace slope degrees and friction scalars. `support: fullFootprint | centerFoot` (controller v1 supports `fullFootprint` only), `grabHeight` and a `drop {canDrop, timeoutTicks}` block are explicit. Material traction scales acceleration and braking.

The foundational schema includes all named movement families as versioned discriminated ability entries. Disabled/absent entries mean unavailable. Unsupported enabled entries produce “unsupported” diagnostics and cannot be treated as feasible edges. Adding an ability definition or solver version must not require changing foothold or collider geometry. Consumer `requiredFeatures` prevents silent loss. Ground jump count and *additional airborne jump* count are distinct; a zero-extra-jump character can still have one ground jump. Profiles pin `controller {key, version}` and collision semantics; changing any relevant content changes their content hash, even if their human-readable name stays the same.

Live state includes position/velocity, support/body, movement mode, jump/dash charges, cooldowns, contacts, active modifiers, grapple attachment and facing. It belongs to Test/runtime state only. Section F specifies the versioned fields; section I specifies fixture tolerances and controller identity.

## E. Navigation architecture

### E1. Representations and guarantees

Use a **directed multimodal graph per movement profile and controller identity**. Source: enabled colliders/footholds, materials, traversal, zones, explicit intent links and conditions. Derived: accessible surface intervals, launch/landing states, air/climb/action edges, hierarchy and trajectory witnesses. Runtime: graph revision, dynamic occupancy and actor-specific conditions/resources. Generated nodes/paths are rebuildable and never map authority.

Ground actors use support intervals and action nodes. Flying/hovering actors use collider-inflated free space with an adaptive grid or visibility graph, respecting flight zones, masks, acceleration and turning constraints. A* over a free-space grid is appropriate for flight; it does not justify tile-cell A* for ground jumping. Swimming is another mode constrained by water volumes and transition anchors. `navigation.modeVolumes` binds volume unions to movement profiles: matching flight volumes constrain the entire body to their union; with none, flight is allowed within world bounds. Swimming requires a matching swim-volume union. Mode entry/exit requires a supported transition witness, not merely overlap with a region role. A route can include mode changes, but only through supported transition edges.

Every result reports profile hash, controller identity, world revision, dynamic assumptions and one of: **verified reachable with replay witness**, **no route found within declared search/sampling budget**, **proven blocked for the stated restricted case**, **unsupported**, **stale**, or **cancelled**. Full continuous reachability for arbitrary advanced movement is not promised.

### E2. Deterministic graph-building pipeline

1. **Normalize and index.** Validate geometry, ownership and masks; resolve initial transforms; build physical AABB spatial index. Extract upward support segments, wall faces and climb paths without inspecting artwork. Prepare inflated obstacles/configuration-space tests for the selected finite collider.
2. **Accessible intervals.** On each foothold, subtract portions where the entire standing collider penetrates an obstacle, lacks required support/contact rules, exceeds slope limits or violates material restrictions. Clip by allowed areas and split at changes in material, direction, hazards, collider clearance, traversal entries, intent anchors and candidate landing boundaries. Finite body overhang is a controller policy; the default fixture requires full bottom-footprint support for stable resting anchors. A slope requires the actual standing-body clearance test, not a horizontal endpoint shrink alone.
3. **Surface transfers.** Create directed walking/running transitions inside an interval and across compatible authored endpoint links. Check stepping/snap limits, tangent velocity, stopping distance, slopes and corner clearance. Moving from a landing point to a launch point must have its own witness or a proven monotone walkability interval. Same-platform points are not interchangeable when hazards or one-way restrictions intervene.
4. **Candidate actions.** Spatial queries select target surfaces/climb entries within conservative jump/fall/dash envelopes. Sample launch boundaries, nearby obstacle/landing critical X positions and an adaptive lattice. Include initial speed bins (rest, run in each direction and refined intermediate values), jump-hold durations and air-control schedules. Analytic ballistic estimates reject impossible candidates cheaply; they do not prove clearance or variable-jump reachability.
5. **Controller replay.** Run candidate input schedules through the exact reference controller used by Test at fixed ticks. Sweep the full collider, not a center point. Detect earliest time of impact, ceilings, walls, one-way crossings, hazards and first valid landing. Reject witnesses that clip corners or land on an intervening platform rather than the target. Store contact/support sequence, terminal velocity/resource state and dependency bounds.
6. **Climb/mode transitions.** Resolve ladder/rope entry and exit witnesses with body/hand reach, exit clearance and ability gates; generate directional climb edges with duration costs. Add swim/flight/wall/ledge/grapple links only for supported capability solvers. Explicit scripted/teleport links are conditional registered actions, not physical clearance exemptions.
7. **Resource-state expansion.** Action states include launch/landing coordinate range, velocity class, grounded/climbing/airborne mode, remaining jumps/dashes, cooldown class and relevant ability/condition bits. A coarse interval graph alone loses these constraints. Prefer stable grounded reset states where stopping/charge reset can be verified; retain stateful action nodes where reset cannot occur. Generate multi-jump/dash/wall sequences on demand with bounded action depth, duration and state dominance pruning. Unknown modifier states invalidate a certificate.
8. **Publish atomically.** Sort source and generated keys deterministically; attach a cache key and diagnostics; replace the displayed graph only if document/profile revision still matches. Cancellation or a stale worker reply cannot replace current results.

Walking/slopes/climbing are foundational. Single jump, fall and drop are the first airborne solvers. Multiple jumps, variable dash schedules and wall sequences extend solver modules while retaining source geometry. Grappling/swinging/teleport need dedicated state and clearance models; an ability flag alone does not prove them.

### E3. One-way, drops, dynamic movement

In Y-down, a one-way surface accepts a contact only when the collider was previously separated on the outward support side and approaches the plane: with outward/up normal n, the closest shape-to-plane signed separation was at least the contact skin and relativeVelocity · n < 0. An established support contact may persist while not separating and not suppressed by drop. A character rising from below passes through. “Drop” suppresses the chosen support and welded connected support group until the collider clears it, with bounded timeout; it does not disable every one-way platform for an arbitrary fixed duration. Test near an immediately lower one-way surface. Solid floors remain solid during drop. Edge-fall candidates model launch horizontal velocity and collisions on the way down.

Static caches exclude live door/obstacle state. Runtime blocker changes increment affected physical-region revisions, disable intersecting witness edges, and queue regional regeneration. Every edge stores swept-volume dependencies, including empty space; adding a new obstacle invalidates paths through that space even though it did not previously reference a collider. Deletion may reveal new actions, so rebuild candidates in an expanded capability envelope. A closed door can be represented as a conditional blocker plus an engine action to open it; no route may assume it opens without that capability/action.

Moving platforms require phase/time-dependent boarding, ride and exit states. A static sampled snapshot cannot certify future rendezvous. Initial release may show their source and unsupported navigation; a later solver uses time-expanded states/wait actions over periodic schedules and runtime phase feedback. Aperiodic motion uses local prediction/replanning and qualified reachability. Runtime follows or replans when contact, velocity, conditions or platform phase leave the witness tolerance; it never blindly replays an obsolete input trace.

### E4. Search, costs and scalability

A* uses nonnegative estimated duration plus nonnegative penalties for risk, hazards, restricted materials and designer preferences. Dijkstra (`h=0`) is the correctness baseline. A Euclidean-distance/max-speed lower bound is valid only when every allowed action respects that displacement/time bound; teleports, zero-cost portals or unbounded actions require zero heuristic or a separately proven abstract heuristic. Never subtract preference bonuses into negative edge cost. Directional links stay directed; a jump up does not imply a fall or jump back.

Find the source from the actor's actual support/mode/velocity state; goals are target anchor/region with landing/stance constraints. Run augmented graph search, then replay the entire chained route. Search on the coarse interval graph is a candidate route only; entry state must satisfy each next witness. If chained replay fails, refine or blacklist the incompatible transition rather than display success. Pursuit replans at a bounded rate and on meaningful invalidation; short-range local steering is engine-owned and cannot make an invalid long-range edge legal.

Let S be support segments, K candidate source/target pairs after spatial pruning, B sampled control/state schedules, T ticks per candidate and C average broadphase collision query cost. Baseline generation is approximately `O(S log S + K*B*T*C)` plus geometry splitting. An unpruned all-pairs search is quadratic and unacceptable. Graph search is typically `O((V+E) log V)` with a heap; resource expansion can dominate both V and E. No polynomial bound is claimed for arbitrary ability sequences.

Use 32×32 art chunks, physical region indexes independent of art chunks, per-profile LRU caches, conservative reach envelopes, per-edge dependency bounds, worker cancellation/time budgets and progressive overlays. Compute active viewport/route neighborhoods first. A hierarchy of surface regions can accelerate repeated queries after base graph correctness is established; inter-region portals retain required motion state and do not erase feasibility constraints. Cache generation order and tie-breaks use stable IDs and explicit sampling settings.

Cache identity includes schema/collision contract version, physical geometry/material/traversal/nav-intent hashes, movement content hash, controller implementation/version/hash, fixed timestep and integrator/collision policy, solver version, sampling lattice/tolerances, relevant catalog definitions and dynamic assumptions. Artwork-only changes do not invalidate physical reachability. A profile “version 1” string is insufficient when coefficients changed. Exported derived caches have their own `maplab.navigation` version and may always be discarded and rebuilt by consumers.

### E5. Enemy authoring and proof boundary

Enemy/NPC archetypes are references to a versioned consumer catalog. Map data supplies spawn anchors, profile reference, behavior ID/parameters, route, guard/home/pursuit/leash/aggro regions, respawn policy and encounter/group IDs. Waypoint waits are integer ticks at the map's declared 60 Hz (`waitTicks`, R1); waypoints can be foothold-relative; routes state order, loop/ping-pong/once and required abilities/conditions. Multi-platform patrol validation checks every leg and the return leg for a loop, using that enemy's collider and profile. Stationary actors have zero-travel behavior; flying patrols use free-space routing. Bosses/encounters refer to arena bounds, participants and wave/event definitions.

“Patrol verified” means a complete route replay succeeds under the named controller, initial resources and declared blocker/condition assumptions. It does not prove an arbitrary engine AI will follow it. When runtime events invalidate a route, the behavior contract selects wait, safe stop, home/replan or registered fallback; never teleport or grant a missing jump silently. The editor stores fallback intent and can simulate reference routing, while runtime AI decision making remains in the engine.

## F. Complete format proposal

### F1. Versioned documents and contract rules

*R1 revision, adopted at ML-003 on 17 October 2026: adds the never-exported `maplab.project` and `maplab.palette` editor documents, reserves `maplab.world`, records prefab provenance and binds named semantic contracts ([R1 F1](2026-10-17-maplab-r1/F-formats.md#f1-format-family)).*

All five proposed families deserve separate versions: maps change independently from tilesets, prefabs and movement models; the export container changes independently from all of them. Use JSON files with descriptive extensions (`.map.json`, `.tileset.json`, `.prefab.json`, `.movement.json`) and explicit `format`/integer `version` headers. Extension alone is never validation. Add a small `maplab.catalog` v1 for closed behavior/action/archetype parameter definitions and optional `maplab.navigation` v1 for derived artifacts. Editor project indexes (`maplab.project` v1) and sidecars are versioned local workspace documents, excluded from consumer bundles.

IDs are persistent authored-domain strings, not selection IDs, filenames or array offsets. Grammar for IDs and catalog keys: `^[a-z0-9][a-z0-9._:-]{0,95}$`. Production creation should allocate lowercase UUID-based IDs once; readable IDs below are valid fixture identities. IDs are unique across all object collections within a map; document IDs are unique across a project/export. Renaming a label never changes identity. A reference must resolve to its expected kind; existence alone is insufficient. Cross-map references explicitly carry map and object IDs. Version numbers are safe positive integers.

Every declared object is closed. JSON Schema 2020-12 uses `additionalProperties:false`, or `unevaluatedProperties:false` at composed boundaries. Required fields below have no silent defaults on import; optional fields are explicitly marked. A catalog-bound `params` object is closed by its referenced definition, not an unrestricted property bag. Schemas are bundled/pinned locally; validators must not fetch remote `$ref` URLs. Semantic validation then checks IDs, references, geometry, bounds, capabilities and source ownership. Duplicate JSON keys are rejected before ordinary parsing can discard them.

Named semantic contracts are not documents: `maplab.collision` v1, `maplab.reference-controller` v1, `maplab.camera` v1 and `maplab.climb` v1 each have prose rules and conformance fixtures. A map's `requiredFeatures` and a profile's `controller` bind them, and unknown required contracts fail closed.

Supplemental invariants: each catalog `(key,version)` is unique across the dependency closure. Every reference/call checks its expected definition kind (behavior/action/archetype/event/effect/traversal/modifier), required fields, ranges and references. A behavior cannot masquerade as an action. `actorCategories` denotes declared gameplay roles `player`, `enemy`, `npc` derived from actor creation kind, independently of physical collision categories such as `actor`. `Region.role` is its primary editor purpose; the same validated geometry may serve several compatible AI constraints.

Body masks/categories must be declared in the collision contract; a collision pair participates only if the contract's symmetric mask test succeeds. `shapeId` (replacing `shapeIndex`) and `edgeIndex` refer to a stable source shape and its vertex order, not decomposed shapes. Rect edge order is top/right/bottom/left; polygon edge i is vertex i→(i+1) modulo count. For a solid edge, body collision category/mask/enabled and geometry are authoritative; foothold category/mask must agree. Effective support is available only when body and foothold are enabled, but disabling support cannot remove the still-solid body face. The controller reports an unregistered solid face contact; navigation cannot treat it as authored walkable support. Body material governs bulk/side contacts; foothold material is an explicit top-face override for traction/conveyor/effect. One-way footholds own their own collision fields. Solid foothold endpoints must exactly match the referenced exposed edge (possibly reversed) in the same frame. Vertex-order edits must remap edge references within the same transaction; reordering shapes changes no reference. Visual `bodyId` attachment uses body-local transforms. An entity's `visualId` binds a visual template to its resolved anchor/facing; one visual cannot be simultaneously body- and actor-owned. Prefab layer slots resolve to target layer IDs during expansion; exported maps contain expanded content, so no engine prefab evaluator is required.


Visual children use parent-local transforms, inherit their parent layer and compose root-to-leaf. A root may be world-owned, rigid-body-owned, or actor-owned through `Entity.visualId`; ownership is exclusive and inherited by children. A child cannot declare a different body/actor owner. Visual parents cannot form cycles; sibling order is explicit. Layer groups multiply opacity/visibility but never introduce physical transforms. Assets are document-local: map visuals resolve map assets; tiles resolve their tileset assets; prefab assets/flags/presentations are copied with new IDs and remapped references on expansion. Dependencies identify documents by stable ID, while asset paths always resolve at bundle root. A copied visual from a tileset/prefab receives a map-owned asset record or an explicitly resolved dependency binding; no global filename lookup. Colors are literal `#RRGGBB` or `#RRGGBBAA`, never CSS expressions/URLs. Frame asset and duration arrays have equal nonzero length; duration ticks are positive. Terrain intent contains at most one record per cell.

Trigger sensors test the full actor collider against region interiors; mere tangency is outside. Swept overlap detects fast crossings, with enter/exit ordered by time of impact, then trigger ID and enter before exit for exact ties. Initial spawn inside emits enter at tick zero. Sensor evaluation follows collision resolution; actions queue in authored order and apply at the end-of-tick event boundary, so geometry changes take effect on the next physics tick. Simultaneous actors use stable actor-instance-ID order. Runtime owns overlap sets, one-shot completion and actor instance IDs. Event parameters and condition leaves use validated data only; compound conditions have maximum depth 8 and 256 leaves, and no text expressions.

Ability entries are unique by `(kind,mode)` where relevant. All tick counts (abilities, motion legs, frame animations and authored durations) refer to the map's declared 60 Hz clock; no document carries a separate rate. Motion has at least two points and exactly points.length-1 positive leg durations. Loop paths explicitly repeat the first point at the end; ping-pong reverses the same legs. Initial phase is within the resulting period (or once-path duration). Waypoint waits are nonnegative integer `waitTicks`. A future ability-specific schema version can coexist with v1 geometry, with `requiredFeatures` declaring support. Unknown properties and unknown required types reject; an older application may preserve an unsupported document byte-for-byte in read-only mode, but must not rewrite it destructively.

Navigation cache keys are derived content keys, not editor selection identifiers. Every edge resolves node/witness keys and source references; witness inputs are complete control snapshots held until the next listed tick. Resource keys are declared by their solver contracts, and values are finite bounded counts/cooldown ticks. Conditional edges are not a verified unconditional route. Cache source hashing covers canonical physical bodies, footholds, materials, traversal, nav intent, referenced mode/override regions, collision contract and relevant catalog definitions; settings/profile/controller hashes cover their respective full content. Checkpoints use controller-state precision (integer su and su/tick), not authored-coordinate precision; witness inputs are run-length records keyed by `fromTick`. Nav payloads may be omitted entirely; cache chunking/compression is deferred rather than an undocumented binary format.

### F5. Canonicalization, versions and migrations

*R1 revision, adopted at ML-003 on 17 October 2026: adds the library serialization form; JCS export bytes are kept ([R1 F4](2026-10-17-maplab-r1/F-formats.md#f4-serialization)).*

**Library form** (files in the library folder): UTF-8, LF, trailing newline, 2-space indentation, key order equal to the published schema's `properties` order (`format`, `version`, `id` first), domain-ordered arrays and shortest round-trip numbers. It is deterministic and diff-friendly; MapLab's first save rewrites hand-formatted sources into it. **Export form** is the canonical JCS encoding below.

Normalize domain collections by persistent ID before JCS, except semantic order: layer siblings use `(order,id)`; vertices, animation frames, motion legs, route waypoints, condition/action sequences and paint order preserve specified order. Chunk lists sort numeric row then column; each contains exactly 1024 row-major entries. Mask/tag sets sort lexically and reject duplicates. Catalog entries sort by `(key, version)` and abilities by `kind`; the sorted string sets also cover ability lists, actor categories, profile IDs, override actions, body IDs and expanded IDs. Normalize commutative set-like reference arrays; do not reorder a sequence just to make a hash convenient. Preserve string content; names may be Unicode, while IDs and exported paths use the restricted ASCII grammar.

JSON byte encoding is RFC 8785 canonical UTF-8, **without** trailing newline. SHA-256 covers those exact bytes and unmodified approved asset bytes. Manifest files sort by normalized path; documents sort by ID. ZIP v1 uses STORE, lexical entry order, DOS timestamp 1980-01-01 00:00:00, fixed file attributes, no comments/extra fields, explicit UTF-8 flag, and no directory entries. Initially cap archives below classic ZIP limits (512 MiB, 20,000 files); ZIP64 or compressed transport is a new container contract. No current timestamp, export nonce, absolute path, local handle, editor selection or recent-file metadata may enter reproducible output. Generator version changes are an intentional input change; identical authored content, dependencies, generator and options must yield identical bytes.

App versions are semver; document format versions are independent integers. Every field addition/removal that changes the closed grammar needs a new document version, unless it is a new already-defined catalog/ability definition supported by the extension contract. Required features are fail-closed. Consumers must explicitly declare support for exact versions or a tested migration chain; they must not accept `version <= latest` blindly. Initial exporter writes v1 only. After v2 exists, retain published v1 schemas/fixtures and a pure v1→v2 migrator; the editor should support the current and immediately preceding major format through migrations. Older documents remain recoverable as source even if migration is unavailable.

Migrations are explicit, deterministic and copy-on-write: validate old version → migrate → validate new version and references → show semantic changes/unsupported assumptions → save a new revision with an external migration report. Never invent collision from art, ground anchors from rig feet, or ability feasibility during migration. IDs remain stable unless a documented split requires an explicit remapping table. Independent engine importers can choose to reject unsupported versions rather than include editor migrations. Runtime save-state migrations belong to the engine and are keyed by authored map/bundle identity.

## G. Engine integration architecture

### G1. Exact load sequence

1. **Read bounded archive/directory input.** Reject unsafe paths, duplicate entries, symlinks, expansion-limit violations and unexpected root files. Do not extract untrusted names to arbitrary filesystem paths. Parse the manifest with duplicate-key detection and the published v1 schema.
2. **Verify bytes before use.** Validate each listed file's length and SHA-256. Require complete inventory: every non-manifest entry is listed, every listed entry exists, and there are no path aliases. Verify a trusted outer bundle digest if the game's distribution system supplies one. Hash success alone does not prove publisher identity.
3. **Negotiate contracts.** Check every document format, collision/controller requirement, capability definition, camera model and gameplay handler. Reject unknown required contracts with a precise capability report. Optional foreign presentation/derived data can be retained or skipped only where the contract explicitly permits that; mandatory world collision cannot be ignored.
4. **Validate closure.** Parse authored documents against pinned schemas; validate IDs, kinds, asset references, geometry, source edges, cross-map targets and catalogs. Resolve cycles in map dependency graphs with a visited set; map-to-map portal cycles are allowed, document/anchor/parent cycles are not. No network resolution is implicit.
5. **Construct world source.** Build an engine-specific visual scene, collision world, stable source-ID→runtime-handle table and support/traversal indexes. Decompose/merge physical shapes only with source identity mapping. Apply approved unit/Y-axis conversion once at the adapter boundary, including normals, slopes, velocities and camera bounds. Build collision before spawning actors.
6. **Resolve movement.** Bind archetypes to movement profiles and the engine's controller implementation. A map can load without claiming test parity; unsupported required movement/collision semantics block playable activation. Optional graph caches are accepted only if their full identity matches a controller the consumer has tested. Otherwise rebuild or omit AI navigation according to explicit consumer capabilities.
7. **Spawn safely.** Resolve starts and foothold/body-relative anchors through the stance solver. Reject overlapping/unsupported required starts. Create NPCs/enemies/objects from registered archetypes; attach physical bodies, presentation bindings and spatial AI configuration. Initially inactive encounter spawns remain authored definitions until activation.
8. **Activate runtime systems.** Register trigger sensors, conditions/actions, encounter lifecycle, camera/audio/environment zones and portals. Dispatch initial enter events under the declared tick boundary. Engine AI, combat, inventory and quests remain engine systems; the map only references their validated identifiers and parameters.
9. **Handle change.** Doors/destructibles/platforms change a runtime overlay keyed by source ID, not the authored JSON. Increment physical/navigation revisions, invalidate affected paths, and replan using the actor's actual state. Runtime motion phases, blocked edges and trigger one-shot state are never saved back as map edits.
10. **Portal/save lifecycle.** Resolve a destination stable map/start identity, load/validate its bundle if needed, instantiate its physical world, place actor through destination stance resolution, then resume. Prevent immediate touch-portal loops with an explicit engine transition token/reentry rule. Save mutable state separately, binding it to authored map/bundle and engine-save schema versions.

A consumer may use a small, independently versioned format library, but it must not load MapLab's React app, reducer, editor file adapters, UI assets or test-mode runtime. The published JSON Schemas, numerical/controller specification and fixtures are sufficient to implement a separate importer. An independent proof consumer must read exported bytes, not receive the editor's in-memory objects.

### G2. Actor composition and RigLab import

*R1 revision, adopted at ML-003 on 17 October 2026: `groundContact`, the facing-left depth profile and 60 Hz frame indexing ([R1 G3](2026-10-17-maplab-r1/G-engine-integration.md#g3-actor-composition-and-riglab-presentation-kept-with-r1-specifics)).*

The actor's physical foot-reference transform/velocity/facing is authoritative. Its supporting ground anchor/contact manifold is physical output. Presentation is downstream: transform → explicit rig ground-reference binding → sampled skin/skeleton/animation → optional weapon artwork. A source surface anchor first resolves to a shape-safe actor stance, especially on slopes. No animation frame may change body dimensions, collision masks, velocity, movement charges, triggers or combat state.

For rig-space point `p`, authored rig ground anchor `a`, presentation anchor `Pv`, world scale `s` (the exact ratio `worldUnitsPerRigUnit {num, den}`), facing reflection `f` and visual rotation `R`, use `Pv + R * diag(f*s,s) * (p-a)`. `Pv` is the physical foot reference `P` when `groundContact` is `"footReference"`; with `"supportLine"`, a grounded actor's art is drawn at `Pv = (P.x, groundY(support, P.x))`, on the line under its center, while physics keeps `P`. Reflection applies to the entire part transform and appropriate paint order, not only bone positions; facing left uses the rig depth profile's `facingLeft` side map for paint order. Default visual rotation is zero; aligning artwork to slopes is an optional presentation setting and never rotates the physical collider implicitly. Root translation remains visual; never recenter each frame on the lowest animated foot or extract implicit root motion into physics.

The isolated importer must validate `riglab.export` v1, `riglab.rig` v1, `riglab.anim` v3, optional `riglab.weapon` v1 and `riglab.baked` v1, safe relative paths, file hashes, bone references, finite transforms, frame lengths and supported resource limits. Names are mapped within the imported namespace; they do not replace MapLab actor IDs. Preserve approved foreign bytes under a bundle-specific prefix, and hash those exact bytes in MapLab's outer inventory. Original RigLab manifest paths retain their own root-relative resolution inside that prefix.

**First presentation implementation should require validated baked v1 for animated preview.** The controller runs at 60 Hz and `riglab.baked` holds one frame per tick, so presentation picks frame `(tick − stateEnterTick) mod length` for loops, or clamps for one-shots, with no resampling; engines at other display rates interpolate visually without touching physics. An otherwise valid unbaked bundle can be stored/referenced and displayed as a skeleton/static placeholder; do not import RigLab's IK/weapon solver just to animate it. A generic debug character always works without a bundle. RigLab exports lack skins/palettes/art/hold files, so `RigPresentationBinding.artSlots` explicitly associates approved separately imported assets with rig slots. This is a typed nested binding, not a JSON file smuggled into the image-asset union. Palette-to-color conversion, if supported later, needs its own validated binding version; no arbitrary CSS is accepted.

Semantic mappings are data: `locomotion.idle`, `locomotion.walk`, `locomotion.run`, `locomotion.jump.rise`, `locomotion.fall`, `climb.ladder`, `climb.rope`, `dash.air`, `wall.slide`, `ledge.climb`, `swim`, `fly`, and consumer action IDs. Each maps to an existing animation name or a declared fallback chain; cycles/missing targets are invalid. Missing advanced clips use a generic pose/placeholder while the physical action still works. Current RigLab's idle/walk/jump/attack/hit kinds are evidence of those current files only.

### G3. Authored, derived and mutable data

| Data | Owner | Persistence |
|---|---|---|
| Geometry, assets, layers, material definitions, profiles, catalog calls, starts, routes and explicit links | Author/MapLab source | `.map/.movement/.tileset/.prefab/.catalog` documents; exported exact bytes |
| Spatial trees, convex decomposition, resolved anchors, graph edges, witnesses, visibility batches | Rebuildable tool/consumer output | Optional caches with complete identity; never required map truth |

An engine save should at minimum bind engine-save version, map IDs, authored bundle digests, physical-controller identity and per-source-ID overrides. Actor-instance IDs are engine-owned and distinguish multiple live instances of one spawn. Content updates require an explicit engine save migration or compatibility refusal; never silently reinterpret an old destroyed-door ID after that ID was reused.

## H. Editor technical architecture

### H1. Source modules and dependency direction

*R1 revision, adopted at ML-003 on 17 October 2026: `src/library` replaces IndexedDB-first storage, and a boundary check enforces the dependency rules ([R1 H1](2026-10-17-maplab-r1/H-editor-architecture.md#h1-source-modules-and-dependency-direction)).*

```text
schemas/                 published closed JSON Schemas (one per format version)
conformance/             fixtures: maps, profiles, input traces, expected traces/outcomes (I2)
placeholder-library/     read-only library used by tests/CI; holds the forest example (F3)
scripts/dev.mjs          npm start launcher; check/contract scripts
src/contracts/           parse (bounded, duplicate-key-rejecting), schema + semantic validation, canonical JSON
src/geometry/            integer su math, exact floorDiv, segments, shapes, spatial grid
src/physics-reference/   maplab.reference-controller v1 (I1): pure, no editor/React imports
src/navigation/          intervals, candidates, witnesses, search, flight/swim planners
src/domain/              normalized document model, commands, remapping, migrations
src/editor/              per-document session, tools, selection, history, inspectors' view-models
src/render/              Canvas 2D passes, chunk caches, picking, one world↔CSS transform

src/export/              closure, JCS bytes, manifest, STORE ZIP
```

Dependency rule: UI/tools → domain/contracts; renderer/library/export/physics/navigation depend on contracts and pure geometry as needed; contracts depend on none of those. `contracts`, `geometry`, `physics-reference`, `navigation` and `export` import no React, DOM, editor, library or app code; `physics-reference` imports only `geometry` and contract types; nothing imports RigLab or Hexframe source. Navigation and Test share one reference movement kernel, not two approximate simulators. Workers use explicit message schemas and transfer immutable snapshots/deltas. Engine consumers may adopt published schemas/fixtures without adopting any source module. A `check:boundaries` script, part of `npm run check`, fails on violations and prevents accidental React/editor/RigLab/Hexframe dependencies in pure packages.

### H2. State and history

Each open map has a normalized authored model keyed by persistent IDs, revision identity, saved content digest and command history. Assets use an immutable content store; ID/path metadata is separate. Session state owns selection/tool/active layer/snap settings and unsaved pointer preview. A separate derived store owns validation indexes, render chunks and navigation results by source/profile revision. Test owns a frozen document snapshot and live simulation state. Starting Test does not reset author history; stopping discards simulation state. Editing while Test is running stops/restarts from an explicit new snapshot.

Commands record intent and compact inverse data: `PaintCells`, `MoveObjects`, `SetProperties`, `SplitFoothold`, `JoinFootholds`, `RetargetReference`, `ResizeBounds`, `PasteRemapped`, `ApplyPrefab`. Bulk paint stores only changed cells/chunks and before/after values. One pointer gesture commits once; Escape/pointer cancellation commits nothing. New edits clear redo. Undo/redo includes reference rewrites atomically. Dirty state compares saved revision/content identity, so undo back to saved content returns clean. Selection/pan/cache builds are not undo entries. Default history budget: 64 MiB per active document with periodic compressed checkpoints; dropping old undo entries is explicit and never drops authored changes. Avoid whole-map clone on every pointer move or cell paint.

### H3. Rendering and hit testing

Canvas 2D is the initial world renderer: offscreen/pre-rendered tile chunks, sprite/frame batches, viewport culling and independent canvas overlay passes for physical geometry, navigation, zones and handles. DOM/React owns controls and hierarchy accessibility. A limited SVG overlay is acceptable for a small active selection or crisp handle geometry; do not create one DOM/SVG node per terrain cell. Sanitize SVG assets to inert image/bitmap sources; do not inject imported SVG markup into the DOM.

Use one affine transform module for rendering, picking, snapping and screen-space handles. Cache world bounds and query a uniform grid/R-tree-like spatial index for visible/pickable objects. Pick in reverse render order with geometry-aware tests and CSS-pixel tolerances; physical tool modes filter to physical objects without hiding artwork. Camera-space backgrounds are excluded from world selection unless specifically selected in the hierarchy. Device-pixel-ratio and pixel-perfect rendering settings affect the backing buffer only.

WebGL is deferred until benchmarks show Canvas 2D cannot meet targets for visible sprites/tile effects, or the product needs GPU effects. Keep render commands backend-neutral enough to replace batching without changing map JSON. Do not spend MVP scope implementing two complete backends. OffscreenCanvas is an optional acceleration after feature detection; navigation workers are useful independently of it.

### H4. Project storage and safe assets

*R1 revision, adopted at ML-003 on 17 October 2026: a library folder written through a loopback plugin, the RigLab pattern, replaces IndexedDB-first storage; the limits table is kept ([R1 H4](2026-10-17-maplab-r1/H-editor-architecture.md#h4-library-storage-and-assets-changed-riglab-pattern)).*

The library resolves to `MAPLAB_LIBRARY`, else `~/Documents/MapLab/` when it holds `maplab.project.json`, else the read-only `placeholder-library/`. Library layout (editor workspace, not an export requirement):

```text
maplab.project.json            index with per-document sha256, written LAST (commit point)
maps/<map-id>.map.json         movement/<id>.movement.json   catalogs/<id>.catalog.json
tilesets/<id>.tileset.json     prefabs/<id>.prefab.json      palettes/<id>.palette.json
assets/<sha12>/<name>.<ext>    sanitized imported copies; originals are never modified
presentations/<id>/…           verbatim validated RigLab bundles
exports/<bundle-sha12>/ (+ .zip)
backups/<UTC-stamp>/…          previous bytes of every replaced/removed file
.maplab/cache/                 derived caches (deletable)
```

The local project index, `maplab.project.json`, maps stable document IDs to safe relative paths with per-document SHA-256 digests and is written last on every save; it is not a runtime world manifest. Copying/renaming files updates that index, not cross-map identities. Palettes are local authoring aids expanded to literal colors/tiles in exports; if runtime palette swapping later becomes required it needs an explicit versioned presentation contract.

Library writes go only through dev-server endpoints under `/__maplab/`. Each accepts only a loopback `Host`, `Origin == http://<Host>`, same-origin `Sec-Fetch-Site` when sent and a JSON content type, with bodies bounded at 64 MiB per document and 128 MiB per save. The host check lives in the plugin itself, because the framework host check runs too late; the placeholder library refuses writes. Save re-reads the project index and affected files, refuses any file whose current digest differs from the client's `baseDigest` and returns the conflict, validates the merged library including cross-document references, copies files about to be replaced into `backups/<stamp>/`, writes each file to a temporary file then `fsync` and rename, writes `maplab.project.json` the same way **last**, deletes removed files and emits a saved event that the watcher ignores for its own paths. On load, a document whose digest does not match the index means the previous save was torn; MapLab offers "keep file" or "restore from the newest backup" and never guesses. IndexedDB journals unsaved edits as drafts only; it is never the authority for a saved document.

For a possible hosted or static mode (ML-042), optional user-selected directory/file handles run directly from Open/Save user activation in a secure context. Feature-detect each picker/operation, recheck permissions on restored handles and keep the fallback. Validate before overwrite, compare the external revision/hash to the last opened version, and refuse stale overwrites pending user conflict resolution. A directory save stages a new revision, validates it, writes a root pointer/manifest last and retains the previous valid revision plus a recovery journal. Per-file close is not directory-wide atomicity. On startup, choose the newest fully validated committed revision or offer recovery. One active writer per project/document; other tabs are read-only until an explicit takeover. Imported external libraries are read-only; project-owned copies are explicit.

Asset/archive limits are proposed initial security budgets, independently configurable downward by consumers:

| Input | Initial limit/policy |
|---|---|
| Export/import container | 512 MiB expanded total, 20,000 files, 64 MiB per JSON document, explicit aggregate accounting before allocation; reject nested archives except bounded recognized foreign-bundle processing |
| Raster | 16 MiB encoded, ≤4096 per dimension, ≤16 megapixels; decoded asset cache budget 256 MiB and cancellation |
| SVG | 2 MiB, 20,000 nodes, 200,000 path commands, no DTD/entities, scripts, event attributes, `foreignObject`, external URLs, imports or animation; constrained literal fills/strokes and approved geometry only |
| Geometry/conditions | Max 4096 vertices per source polygon; max 1 million occupied cells/map; condition depth 8/256 leaves; reference depth/graph cycle checks |
| Paths | ASCII safe POSIX components, max 240 bytes full path; no schemes, absolute/drive paths, `.`, `..`, empty components, backslashes, NUL, percent-encoded aliases, reserved device names, trailing dots/spaces or case-fold aliases |

Use a structural SVG parser/allowlist and inert image rendering consistent with [SVG processing modes](https://www.w3.org/TR/SVG2/conform.html#processing-modes). Hexframe's trusted-internal-markup regex is not sufficient for imported assets. Reject rather than silently rasterize unsupported SVG features. If a deliberate conversion is later added, version it, preserve the original source, and hash/export the approved result explicitly. ZIP entries and local helper realpaths, if any, must stay under their granted root; never honor symlink escapes. No arbitrary network asset URLs or implicit remote service is required. Audio files are bounded and decoded only through approved media APIs; they are never executable assets.

### H5. Measurable performance targets

Baseline benchmark (owner ruling, 2026-10-27): Apple M4 CPU, 24 GB RAM, 1440×900 CSS viewport, DPR 2, a pinned stable Chromium build with hardware acceleration; record browser/OS/controller/build identity and p50/p95 over five warm runs. Test at least one supported non-Chromium browser for fallback correctness. Targets are proposed acceptance criteria, not measured claims.

Standard large fixture: 100,000 occupied cells, 20 visual layers, 5,000 world objects, 5,000 collision shapes and 10,000 footholds spread across a long multi-level world; visible subset ≤10,000 tiles/1,000 objects. Stress fixtures separately approach file limits and intentionally dense physical geometry.

## I. Validation and acceptance plan

### I1. Reference controller identity

*R1 revision, adopted at ML-003 on 17 October 2026: the reference controller is 60 Hz integer ([R1 RC0–RC4](2026-10-17-maplab-r1/D-reference-controller.md#rc0-identity-and-purpose)).*

Define `maplab.reference-controller` v1 and `maplab.collision` v1 before calling a preview route verified. The first controller is kinematic, fixed **60 Hz**, upright rect collider, X-right/Y-down, with deterministic input per tick; capsules remain a declared unsupported collider until their solver/conformance lands. Arithmetic is integer: positions in su (1/256 WU), velocities in su/tick and accelerations in su/tick². Every state value and intermediate is a safe integer; division is exact floor division (estimate with `Math.trunc`, then correct with one exact multiply-compare). No transcendental `Math` function, `Math.hypot` or float state survives between ticks, so identical inputs give identical traces in V8, JavaScriptCore, SpiderMonkey and any exact integer port. This is a reproducible reference model, not a claim of bit-identical behavior in every engine.

Tick order ([RC4](2026-10-17-maplab-r1/D-reference-controller.md#rc4-normative-tick-order)): snapshot input and conditions and validate the old state (initial overlap of a blocking face is `invalidState`) → climb transitions → ground transitions (jump, drop, airborne jump) → horizontal velocity → move X: sweep against blocking faces, re-stance across welds and catch walkable slopes → move Y: ceilings while rising, otherwise land on support faces under the one-way crossing rule (the body bottom was at or above the face at the start of the tick) → gravity after moving (Hexframe order) with hold and release → drop suppression → plane and facing → sensors and the end-of-tick action queue. At most eight contact resolutions per axis per tick; exceeding them reports `contactBudget` rather than tunneling. Equal contacts resolve by body ID, then shape ID, then edge index; foothold ties by ID. Axis-separated motion is a declared semantic, not an approximation of a continuous sweep, and fixtures pin its corner behavior. Moving-platform carry, push and squish follow Celeste semantics when ML-032 adds them; never apply overlap recovery as a second copy of rider carry.

Ground speed is horizontal (MapleStory-like), scaled on slopes by the profile's `uphill`/`downhill` ratios rounded toward zero; air speed is horizontal. Acceleration approaches the commanded signed target by `floorDiv(acceleration·traction, 256)` per tick on the ground (`air.acceleration` airborne); releasing input brakes toward zero by `floorDiv(braking·traction, 256)`; never overshoot the target or zero. Conveyor su/tick adds along the support's a→b direction. Ground-jump impulse sets `vy=-impulse`; gravity is added after moving. Hold gravity `jump.holdGravity` applies only while rising, held, and below `holdTicks`; on the first rising tick after release `vy = trunc(vy·release.num/release.den)`, once; then `vy` clamps to `air.maxFall`. The forest player profile holds for zero ticks, so the first jump fixture is fixed height. No coyote time, input buffer, auto-step or actor-to-actor collision is implicit in v1; adding those policies requires a new supported controller contract or explicit parameterized successor. Wall contacts cancel inward normal velocity; support classification uses the normal/slope contract. Initial overlap never counts as a clear sweep.

These semantics must be turned into executable numerical fixtures in ML-017/018 before nav certificates. Navigation generation and Test call the same implementation entry point. A future engine declares fixture compatibility for a particular profile/controller/precision policy. It may use another solver, but must rebuild paths under that solver or qualify compatibility; matching only gravity and jump impulse is insufficient.

### I2. Fixture matrix

*R1 revision, adopted at ML-003 on 17 October 2026: a `conformance/` package with integer, run-length fixtures and updated numbers ([R1 I2](2026-10-17-maplab-r1/I-validation-acceptance.md#i2-conformance-fixture-package-conformance)).*

Long trajectories use bounded intermediate checkpoints, not only terminal proximity. Fixture-specific tolerances must be justified and published; increasing tolerance to hide tunneling or wrong support is forbidden. Passing fixtures demonstrates tested compatibility, not a universal mathematical equivalence proof.

### I3. Validation layers and release gates

Validation runs in stages: bounded bytes/asset parsing; closed schema; document and cross-document references; exact geometry; source semantics/capabilities; optional expensive profile reachability; consumer/export closure. Diagnostics carry stable code, severity, document ID, object ID, JSON path, world bounds and suggested repair. Errors block consumer export. Warnings cover intentional off-bounds decoration, unused assets, unsupported optional preview and conditional routes; a warning cannot suppress missing required physics support. Navigation is regenerated only for selected required validation profiles; the editor never pretends to exhaust all future profiles.

Unit tests exercise pure geometry/commands and genuine invariants. Contract/property tests exercise normalization, remapping and canonicalization. Browser E2E covers real pointer capture/cancellation, keyboard focus, paint transaction history, file fallback and overlay toggles; static rendered markup alone is insufficient. Independent consumer tests parse final bytes in a separate harness with no editor imports and verify hashes/references/geometry construction. ## K. Architectural decisions and risks

### K1. Decisions and rejected alternatives

| Decision/default | Rejected alternative | Why / cost of changing later |
|---|---|---|
| Standalone authoring app and independent consumer contracts | Embed RigLab/Hexframe editor/engine | Keeps world authoring useful independently; later coupling would infect deployment, licensing and runtime authority. |
| Orthogonal side-view X-right/Y-down WU, explicit art density | RTS cells or CSS pixels as universal coordinates | Supports jumping/vertical maps and engine scale conversion; axes/quantization are expensive to change after fixtures/assets exist. |
| Explicit support geometry separate from solids and art | Derive authoritative collision only from tiles | Supports slopes/floating/one-way/body-owned surfaces; requires more authoring/validation but prevents visual edits changing gameplay silently. |
| Shape-safe stance distinct from geometric support anchor | Put upright box bottom-center directly on every slope | Prevents penetration and profile-dependent spawn errors; must be frozen before physics/navigation conformance. |
| Directed stateful action graph and witness replay | One node per platform, point-distance links, tile A* | Needed for finite-body clearance, velocities/resources and different actor capabilities; costs computation and disciplined uncertainty reporting. |
| Source geometry/intent authoritative; generated graphs optional | Persist generated path as canonical map | Enables engine controller differences and future solvers; optional caches require identity/invalidation rigor. |

### K2. Risks, open choices and bounds

**Controller parity is the largest risk.** Publish integration/contact/drop/stance rules and fixtures, not just coefficients. Engines that choose another solver must rebuild under that solver and report tested compatibility. Surface-anchor resolution is profile-dependent; editor inspectors should show geometric anchor and resolved body pose together.

**Navigation completeness and cost are bounded.** Finite candidate sampling can miss routes; advanced resources cause state explosion; moving geometry adds time. Preserve explicit budget/unsupported/conditional statuses, witnesses, cancellation and scoped proof claims. Learning-based movement controllers or arbitrary continuous optimization are not an MVP dependency. [D* Lite](https://idm-lab.org/bib/abstracts/Koen02e.html) may later repair graph search after valid edge changes, while [SIPP](https://publications.ri.cmu.edu/sipp-safe-interval-path-planning-for-dynamic-environments) informs time/safe-interval planning; neither generates platformer collision-feasible jumps automatically.

**Storage availability is variable.** Handles can lose permission and browser storage can disappear. Distinct saved/recovery state, validated exports, backups and journal recovery are required. Multi-file saves are recoverable, not globally atomic. Offline/local authoring is a product boundary; hosted static delivery can be decided separately.

**Asset and schema extensibility can become an execution loophole.** Keep imported SVG inert and bounded, catalogs data-only, extension versions required, and handler implementation registration in the engine. An unknown required handler is a capability error. Never “make it work” by evaluating strings or loading arbitrary URLs.

**Library/source assumptions must be refreshed.** RigLab exports can evolve, current advanced clips do not exist, and cached Hexframe web descriptions were stale. Pin versions/source hashes and maintain import fixtures. There is no inherited map runtime API from either repository.

Unresolved choices are bounded so ML-001 does not require redesign: public/private visibility and final code-license approval before public release; eventual static hosting target; future engine/physics backend and its verified adapter; compressed/ZIP64/streaming container version; live recursive-prefab overrides; rotating/deformable physical bodies; accessibility beyond required keyboard/control operations; and product-specific enemy/quest/combat catalogs. Defaults in this document let foundational local authoring proceed. None permits rewriting authored geometry, hiding unsupported physics, or importing combat authority into the editor.
