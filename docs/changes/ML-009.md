identity only, so a save now compares digests. ML-010–013 build on this workflow.

## Impact

Users run `npm start` and edit a library folder in the browser. The static build has
no endpoint and says so. Behavior:

- **Save** sends every dirty open map in one request. Each map carries the digest
  of the file it was opened from. Content whose digest equals the saved digest is not
  sent.
- **Server checks.** The server re-reads the index and files. It refuses a stale
  base, and a new document whose ID or file already exists. It refuses text that is
  not library form. It validates the merged library across documents, including
  dependency paths against the index. It refuses while another document is torn.
- **Write order.** The server backs up every replaced or removed file and the old
  index into `backups/<UTC stamp>-<save>/`. Then it writes each file by temp file,
  fsync, rename and folder fsync. The index is written the same way, last. Removed
  files are deleted after the index.
- **Torn saves.** A document whose digest differs from the index's is torn, whether
  an interrupted save or an outside edit caused it. MapLab blocks opening it and
  offers "keep file", which records the current digest. It also offers "restore from
  newest backup", which uses the newest backup matching the index and first backs up
  the current bytes. Recovery needs the digest the user saw. MapLab never chooses.
- **The guard.** Only a POST with a loopback `Host`, `Origin == http://<Host>`,
  same-origin `Sec-Fetch-Site` when sent and a JSON type gets through. Bodies are
  bounded: 1 MiB per request, 128 MiB per save, 64 MiB per document, and UTF-8 only.
  Vite 8 runs its own host check before plugins; the plugin keeps its own check
  anyway. The placeholder library refuses saves and recovery.
- **Dirty state.** Equal content identity is clean at once. Other content stays
  dirty until its library-form digest is known, so renaming back to the saved name is
  clean. `baseDigest` (the file bytes) and the saved digest (the library form) differ
  until a hand-formatted file is first saved. Revert keeps the base. A restored draft
  keeps the base it was edited from, so saving it over a changed file is refused.
- **Save As / Duplicate** creates a new map ID and writes it at once. Persistent IDs
  are scoped to their map, so every local identity carries over unchanged into the
  new map's namespace. Self-portals and other references naming the old map are
  retargeted; links to other maps are kept.
- **New map** creates an unsaved map that validates on its own. It has bounds, a
  ground body and foothold, an actors layer and the default player start for the
  chosen movement profile. When the library has a tileset, it adds a tile layer of
  the chosen size.
- **Drafts.** Each dirty document's library-form text and base digest are journaled
  per library. Opening a document offers "Unsaved draft from <time>" to restore or
  discard, with a note that Safari can evict drafts. Drafts of new maps are listed in
  the library. Saving or reverting clears the draft. Journal writes are serialized
  per document.
- **Outside edits.** An outside edit reloads a clean open document. A dirty one gets
  a conflict banner with "Reload from disk".
- **`npm start`** stops a listener on `MAPLAB_PORT` (default 5182) only when its
  guarded identity endpoint proves it is that MapLab dev server. It refuses any other
  process. Then it resets `dist/` and the Vite cache, runs `npm ci` when the lockfile
  changed, builds, starts Vite on 127.0.0.1 and waits for the started process to
  identify itself. It opens the browser unless `MAPLAB_NO_OPEN=1`. Vite restarts
  the dev server when the plugin's code changes, because `vite.config.ts` imports it.
  The launcher hides Vite 8's notice about a future native config loader, which
  would need explicit `.ts` extensions in every import; the bundled loader works.

`src/contracts`, `src/domain`, the schemas, the specification and ML-010–044 are
unchanged.

## Risk

The main risks are a save that overwrites an outside change, a partial multi-file
save that looks complete, a write from another site or a DNS-rebound name, and a
new dependency. Mitigations:

- The stale-base check precedes any write.
- The index is the commit point, and torn documents need an explicit user choice.
- The guard runs before any read.
- Playwright is one exact pin from the official publisher, with no install scripts
  and verified registry signatures. Its browsers come only from
  `npx playwright install`, which CI runs after the canonical check.

Known limits:

- An outside edit and an interrupted save look the same, so both are torn (R1 H4).
- A real crash can leave a hidden `.name.<save>.tmp` file. Readers and the watcher
  ignore it.
- Palettes have no format yet. They are kept and listed but never saved.

## Validation

`npm run check` adds tests in these files:

- `tests/library-writer.test.ts`: backup-first ordering, temp and rename, index last,
  removal after the index, refusals that leave every byte unchanged, a symbolic-link
  escape, a crash before the index, and keep and restore recovery.
- `tests/library-plugin.test.ts`: the guard matrix and refusals on a real Vite dev
  server, the placeholder, reads, saves, stale refusal, body bounds and UTF-8.
- `tests/library-form.test.ts`: idempotent library form that still validates,
  schema key order, domain order and the `__proto__` member, plus the layout and
  draft-key tests.
- `tests/editor-document.test.ts`: digest dirty state, save completion, revert and
  draft bases, Duplicate retargeting, and New map validity.
- `tests/dev-lifecycle.test.mjs`: the launcher's teardown refusals and readiness.
- `tests/library-boundaries.test.ts`: Node-only modules stay off the browser, and
  there is no picker, OPFS or absolute URL.
- foundation negatives for the browser runner pin and the CI gate.

The owned `conformance/library/` step scripts provide the I2 fixtures: two-map library
reopen, stale `baseDigest` conflict, torn save, backup before replacement, wrong
Host/Origin requests and placeholder write refusal. They run against the real plugin.

`npm run test:browser` runs nine scenarios in WebKit and in Chromium:

- two maps saved together reopen with every persistent ID intact;
- a stale base is refused and nothing is written;
- backups hold the replaced bytes;
- a torn save is resolved by restore and by keep;
- the placeholder is read-only, and a cross-origin page's save is refused;
- drafts survive a reload, and are restored or discarded;
- Save As and New map write valid maps;
- Revert asks first;
- renaming back is clean by digest.

The PR and external ledger record clean install, canonical, browser, security and
policy results, the independent exact-head review and the exact tested head.
