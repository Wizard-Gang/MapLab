# [ML-008] [FEATURE] Add transactional document history and paint deltas

## Change

Record ML-007's verified protected squash and successful main CI, retire it to
history and promote ML-008. Preserve ML-009–044 exactly. Add the pure document
model and history layer that later editing tools build on:

- `src/domain/model.ts`: a normalized map model. Records are keyed by persistent
  ID with ordered ID lists, every other member is frozen JSON, and terrain cells sit
  in sparse packed chunks. The object namespace includes nested IDs.
- `src/domain/paint.ts`: signed 32×32 chunks of packed `Uint32` cells, and the
  compact paint delta. Per chunk, it stores the changed cell indices with before
  and after values, against its own small tile table.
- `src/domain/transaction.ts`: insert, delete, set, field and paint operations,
  each carrying its exact pre-image. A transaction applies completely or not at
  all, and its inverse is exact.
- `src/domain/commands.ts` and `remap.ts`: builders that return null for no-ops,
  stable persistent-ID remapping for paste, and reference rewrites (retarget)
  inside one transaction.
- `src/editor/history.ts`: per-document history with revision, content identity,
  dirty and saved state, save tickets with stale-base refusal, revert, and the
  64 MiB budget with visible drop notices.
- `src/editor/gesture.ts`: one gesture is one entry. A brush stroke holds bounded
  per-chunk working copies, and the base model's immutable chunks are its
  checkpoints.

## Reason

Adopted H2 and R1 H2/H3 require commands with compact inverse data, chunk paint
deltas instead of map snapshots, one entry per gesture, dirty state that tracks
saved content, and a bounded history. ML-009 (save), ML-011 (selection and
clipboard), ML-012 (footholds) and ML-013 (tile tools) all edit through this layer.

## Impact

No user-visible change and no painting UI. The new modules import only
`src/contracts` and each other: no React, DOM, storage or network. A test enforces
this.

The new behavior:

- **Lossless model.** Normalizing and denormalizing the R1 forest and clearing maps
  reproduces their canonical bytes. An absent collection stays absent. Empty chunks
  are omitted on output, and a chunk key keeps its position once created.
- **Persistent IDs.** A transaction can never change a record's `id` or the
  document identity. Duplicate top-level and nested IDs are refused, both at
  normalization and at insert. Implicit groups (entity and encounter `groupId`)
  share the namespace, as in ML-006. Group members may share a group, and a
  group-kind layer may share its own, but no other object may take a group's ID.
- **Own members only.** Only own members are read or written, so names like
  `constructor` or `__proto__` are ordinary absent or present members, never a
  prototype.
- **Paste.** It allocates the smallest free `base-N` ID for every pasted record and
  nested object, deterministically, and never one an existing object or group uses.
  A pasted encounter gets a new group, which its pasted spawns follow. Paste rewrites
  references among the pasted records and keeps references to other maps,
  documents and tiles. References it cannot resolve are reported, not dropped.
- **Dirty state.** Dirty compares content identity. Each state carries the identity
  of the transaction that produced it, and undo or redo restores the identity it
  returns to. So undoing to the saved state is clean. A different edit that happens
  to recreate the saved bytes still counts as dirty, until a save (ML-009) compares
  digests.
- **Save.** `beginSave` issues a ticket holding the immutable model, its base
  digest and the open's session token. `completeSave` refuses a ticket for another
  document, from another open of the same document, or one whose base a later save
  has replaced. Edits made during a save keep the document dirty. Escape returns the
  current state, so a save that completes during a gesture is kept.
- **Sealed entries.** A recorded entry holds a sealed private copy of its
  transaction, and a model never freezes or shares a caller's values.
- **Budget.** Over budget, the oldest entries are dropped, with a
  `history.dropped` notice. The 64 most recent notices are kept, and `dropped`
  counts every dropped entry. Authored content is never dropped. An entry larger
  than the whole budget still applies, but keeps no undo depth.

Two limits are left to later tasks:

- Gesture previews are live, and valid only until the next write, so renderers
  must not cache preview chunks by identity.
- No-op detection is per operation, so a transaction that adds and then removes the
  same record still records an entry. The builders and gestures never produce one.

## Risk

The main risks would be:

- a history that snapshots whole maps;
- an inverse that is not exact;
- a partial transaction;
- dirty state that ignores undo;
- IDs that change or collide.

Each would corrupt authored data or exhaust memory in later tools. Mitigations:

- Every operation checks its pre-image, so a stale or replayed transaction is
  refused rather than misapplied.
- Refusal happens before any new model is returned.
- History accounting counts typed arrays exactly, and JSON as UTF-16 canonical text
  plus fixed overheads. The accounting is enforced after every step.

Periodic compressed history checkpoints (H2) are not needed: exact inverse deltas
recover every retained state. Gesture checkpoints are the base model's chunks.

## Validation

Unit tests cover:

- round-trips of the R1 forest and clearing maps;
- duplicate IDs (top-level, nested, camera zones, dependencies) and invalid IDs;
- packed transforms and negative chunks;
- exact inversion of every operation;
- atomic refusals that name the failing operation;
- a seeded replay of 200 random transactions, which undoes to every prior state's
  bytes and redoes to the last;
- paste and retarget remapping;
- dirty, saved and conflict transitions;
- gestures, the chunk bound, and the memory budget.

A 10,000-cell brush gesture over 100 pointer moves records one entry:

- 10,000 changed cells in 16 chunks;
- at most 100,768 accounted bytes;
- no array shared with any model.

Its undo/redo stays under the 100 ms target in five warm runs.

The first independent exact-head review, at `61856eb`, was blocked:

- Escape discarded a save that completed during a gesture.
- A save ticket from another open of the same map was accepted.
- Inherited member names such as `__proto__` broke exact undo.
- Paste could reuse an existing group ID or share an encounter's group.

`tests/history-review.test.ts` reproduces each of these and the repaired notes as
they were reported, and checks that each is now refused or corrected. That includes
a `src/contracts` source-graph check after an encounter paste.

The owned `conformance/history/cases.json` step scripts provide the I2 fixtures. They
cover the 10,000-cell delta, undo/redo no-ops, one gesture as one entry, duplicate
IDs, the saved-revision conflict, the memory bound and the gesture chunk bound.
Clean install, canonical and security results and the independent exact-head
review are captured in the PR and the external ledger.
