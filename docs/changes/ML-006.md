# [ML-006] [FEATURE] Finalize gameplay and catalog schemas

## Change

Record ML-005's verified protected squash and successful main CI, retire it to
history and promote ML-006. Preserve ML-007–044 exactly. Complete gameplay,
catalog, camera, environment, navigation-intent and presentation contracts,
all fifteen entity kinds, catalog field closure and cross-map references.
Publish the remaining F document schemas without implementing their later runtimes.
Make the existing duplicate-future corruption test target the actual future block
after activation, retaining its original rejection assertion.

## Reason

Independent consumers need closed data contracts and precise reference/handler
validation before ML-007's final-byte bundle harness. A structurally valid
behavior must never masquerade as an action, and portals must resolve in the
explicit dependency closure.

## Impact

`loadSourceGraph` / `validateSourceGraph` accept explicitly supplied authored
source documents, validate the final schemas, geometry and gameplay references,
and return detached frozen documents. They never fetch documents or execute
handlers. Existing partial header/geometry readers retain named deferred scopes.
`validateDocumentSchema` additionally covers project/export/navigation syntax;
byte inventories, library saves and generated navigation remain later tasks.

## Risk

An open parameter object, incorrect handler kind, hidden unsupported controller,
or undeclared destination could be accepted as runnable content. Closed scalar/
typed-reference params bind to catalog fields; every call site checks its kind.
Conditions have depth/leaf budgets. Non-map dependency cycles, wrong reference
namespaces, resolved anchor overflow and duplicate identities reject. Planned
handlers and unsupported movement compatibility remain explicit. Source validity
never certifies controller, AI, camera, environment or navigation execution.
