# [ML-045] [CHORE] Allow plan edits at any time

## Change

Activate ML-045 after the verified ML-039 squash. The change and queue checkers stop binding the plan to the spec's J2 table, to contiguous IDs and to 44 IDs: any PR may add, edit, reorder or remove queued tasks with any queue state. A `[PLAN] Imperative summary` PR on a `plan-<summary>` branch changes only `implementation_plan.md`, takes no task ID and joins no release task list. The plan records the highest ID ever used; a task new to the queue takes an ID above it and a removed queued ID stays retired.

## Reason

Owner ruling, 2026-10-27: "the plan only pr chance is retarded. remove that ... we should be able to change the plan whenever we fucking want". The checker accepted a plan change only as the next sequential task, which blocked plan updates mid-queue.

## Impact

`scripts/check-queue.mjs`, `scripts/check-change.mjs`, `scripts/verify-pr.mjs`, their contract tests, `AGENTS.md`, `CONTRIBUTING.md`, `docs/CHANGE-MANAGEMENT.md`, `docs/DELIVERY-GATES.md` and the plan's header wording. The delivery chain and release chains now follow delivery order (ML-001..ML-030, then each released task once) instead of consecutive IDs. No settings, rulesets, workflows or product code change.

## Risk

A checker change validates its own PR, as at ML-031. A too-loose rule could let IDs be recycled or a plan PR carry other files; a too-strict one could block plan edits again.

## Controls

The delivery chain must equal the legacy IDs plus the release chains in order; release task IDs are unique and above ML-030. `change-id` compares the base and head plans: the high-water mark never falls and every task new to the queue takes an ID above every ID the base used. A plan PR must change `implementation_plan.md` alone, with every commit titled as the PR. It targets the open release branch, or, once the open release has merged and its branch is gone, the next one, which the next task then reuses, so a plan edit is never blocked by the release cycle. The release PR ignores `[PLAN] ... (#N)` squash commits when matching task commits. One controlled commit per task PR, the body sections, release branches, required checks and retiring the delivered task are unchanged. Negative tests cover recycled and retired IDs, a falling mark, a missing mark, plan PRs with other files or wrong branches, and release PRs with unlisted task commits.

## Validation

Local Node is 26.7.0, not the pinned 26.10.0; npm 12.1.0. Locally, `npm ci` and `check:foundation` refuse that Node version, so they ran only in CI's pinned `gate`. Typecheck, build, smoke, change validation and online security (0 vulnerabilities, verified signatures) passed locally on the existing install. Tests run only in exact-head CI.
