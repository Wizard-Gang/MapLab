# [ML-004] [FEATURE] Add geometry and reusable content contracts

## Change

Activate ML-004 after recording ML-003's verified protected squash and main CI.
Retire ML-003 to the plan history and preserve ML-005–044 unchanged.
Extend the local map schema with R1 geometry, layers, visuals, terrain and prefab
provenance; publish tileset and prefab schemas and pure TypeScript validators.
Add explicit JSON Schema `oneOf` support for closed kind unions and owned golden
fixtures for source authority, references, geometry and reusable content.

## Reason

The adopted R1 J4 ML-004 row requires stable shape IDs, exact source edges,
reciprocal welds, clockwise polygons, x-monotone footholds, actors planes,
parent-cycle rejection and prefab layer-slot binding before editor tools exist.

## Impact

Consumers can validate geometry without importing the editor. Tile trace shapes
remain tile-local suggestions with no collision authority. Prefab placement records
validate provenance and layer bindings; content is already expanded. Gameplay,
catalog call/condition validation and profile support/clearance stay explicitly
deferred to their reserved tasks. Missing external tilesets/templates are named
as unresolved, so a local geometry pass makes no dependency-closure claim.

## Risk

Geometry can be structurally valid but refer to the wrong owner or kind. Validation
stages schema checks before semantic loading, resolves shape IDs inside their named
bodies and checks reciprocal links. Polygon predicates use exact quantum values;
signed area accumulates with integers to avoid overflow. Prefab-local IDs and tile
trace IDs have distinct scopes. Expanded objects retain their source kinds and
visual/actor-plane bindings. Entity-anchor chains resolve iteratively with cycle
checks so access attachment cannot be skipped. Consumers must inspect
deferred/unresolved results.

## Controls

One controlled branch, PR and head-guarded squash. No new dependency, network schema
fetch, editor behavior, movement solver, release or deployment. All schemas close
implemented objects and resolve only bundled definitions. Every invalid golden
file has one expected diagnostic; each fixture's SHA-256 pins its final bytes.
Independent review and exact-head verify/change-id/security plus policy read-back
and delivery verification gate the merge.

## Validation

Node 26.10.0 / npm 12.1.0, clean `npm ci`: canonical `npm run check` passed
(foundation/queue/change contracts, typecheck, 246 tests in ten files, production
build and final-asset smoke). `npm run security` passed with zero vulnerabilities,
46 verified registry signatures and 22 verified attestations. No dependency or
lockfile changed. Published schemas validate every valid golden case; invalid
golden bytes produce their one expected code and path. The separate consumer
process resolves forest solid edges without editor imports, using Node's built-in
TypeScript stripping rather than an unavailable TypeScript 7 transpiler API.

Independent review identified invalid visual-layer targets, wrong-kind expanded
prefab objects and unresolved/cyclic entity anchors. These were corrected with
regressions, along with prefab actor-plane slot mappings and motion phase bounds.
Profile-specific support/clearance and gameplay/catalog validation remain explicit
deferred boundaries. Final exact-head review, provider checks and authenticated
policy/delivery evidence are recorded with the PR before protected squash.
