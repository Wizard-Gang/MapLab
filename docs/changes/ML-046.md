# [ML-046] [FIX] Match release commits without a PR suffix

## Change

Activate ML-046 after the verified ML-045 squash. The change checker's release-PR match makes the ` (#PR)` suffix optional on task and plan squash commits and matches the title lazily, so a squash subject with or without the suffix compares equal to its task record.

## Reason

Owner call, 2026-10-27: release r001. A local `check:change` probe of the r001 release PR event rejected it with "Release commits must be one squash commit per listed task": ML-032 (`f697149`), ML-033 (`5a626ea`) and ML-036 (`4d5330a`) were squashed by REST with an explicit subject and no ` (#PR)`. The release branch is published history, so the checker is fixed forward instead.

## Impact

`scripts/check-change.mjs`, `tests/change.test.mjs` and `docs/CHANGE-MANAGEMENT.md`. Task PR, plan PR and release PR rules are otherwise unchanged. No settings, rulesets, workflows or product code change.

## Risk

A looser pattern could accept a non-squash commit on the release PR. The `MapLab release` ruleset allows only squash merges into `release/*`, so every commit there is already a squash; the count, order, ID and record-title comparison still apply.

## Controls

Release commits must still be exactly one per listed task, oldest first, each titled as its record; plan commits must still be `[PLAN]` with a capitalised summary. New tests accept suffix-less task and plan commits and reject a malformed plan commit; the unlisted, missing, retitled and unsquashed-task cases still fail.

## Validation

With the pinned Node 26.10.0, a simulated r001 release PR event fails `check:change` on the ML-045 tip and passes with this pattern. Local `npm ci`, `check:foundation`, typecheck, build, smoke, `check:change` and online security run before the PR. Tests run only in exact-head CI.

## Evidence

Exact tested head and gate, change-id and verify URLs follow in a PR comment once green.
