# [ML-007] [FEATURE] Add independent final-byte fixture reader

## Change

Record ML-006's verified protected squash and successful main CI, retire it to
history and promote ML-007. Preserve ML-008–044 exactly. Add `tests/consumer/reader/`
(the specification's `tests/consumer/` importer location), an independent bundle
reader that runs as its own Node process. It reads final export bytes and the
pinned published schemas from disk and imports only Node built-ins and its own
folder: never `src/`, the editor, React or a bundler. Pin the R1 forest source
documents and export bundle as golden inputs with declared schemas in
`conformance/bundle/`, plus inert mutation records for the negative suite.

## Reason

The adopted G1 load sequence and I3 independent-consumer layer require a reader
that parses exported bytes rather than receiving the editor's in-memory objects.
A second implementation of the byte, schema and reference rules also catches
defects that a consumer sharing the editor's own format library would repeat.

## Impact

`node tests/consumer/reader/read-bundle.mjs --schemas DIR BUNDLE` reads a folder
bundle and prints a JSON report. It performs these parts of G1 steps 1–4:

- a bounded safe-path inventory that rejects symlinks, special files, empty
  directories and alias, hidden or reserved names;
- strict UTF-8 JSON that rejects duplicate keys;
- a canonical manifest with complete inventory, exact sizes, SHA-256 and the bundle digest;
- exact format/version and required-contract negotiation, with each contract
  member checked for its role and duplicate required features rejected;
- independent closed-schema evaluation;
- dependency closure, including the path identity of absent optional dependencies;
- resolution of every reference, catalog entry, portal and asset path inside the
  referencing map's dependency closure, including every movement profile in that
  closure, declared or not.

Two policies follow `src/contracts` and are stricter than reachability: terrain must
declare its tileset directly, and a profile's map-relative refs must resolve in every
map whose closure holds it. A profile `controller` other than
`maplab.reference-controller` v1 is rejected here, where the library only reports
the profile as unsupported.

It checks that each catalog entry exists. It does not check handler kinds, parameter
semantics or the F3 semantic rules (player starts, encounters, condition budgets);
those stay in `src/contracts`. It constructs no world, renderer, engine or navigation.

## Risk

A reader that trusted the editor's objects, accepted `version <= latest`, ignored
duplicate keys or skipped unlisted files would certify bundles a real importer
must refuse. Every diagnostic code has a separate-process mutation record, except
six that no bundle edit can produce; each of those has a named in-process test.
A test enforces that rule. The reader fails closed on unclassified reference and
`{key, version}` members, so a later schema change cannot silently bypass reference
checks.

## Controls

One controlled branch, one PR, controlled commit subjects and a head-guarded
protected squash. Exact Node 26.10.0/npm 12.1.0, no added dependencies, unchanged
lockfile and lifecycle denial. Independent review plus clean install, canonical,
security, policy, exact-head CI and authenticated delivery verification precede
merge; resulting-main checks and branch deletion follow it. No release/deployment.

## Validation

A separate Node process, started from a scratch copy holding only the reader folder
and `schemas/`, reads the unchanged R1 export bundle. It verifies bundle digest
`0a39dafd…`, all seven documents and both maps, and resolves the reciprocal
forest/clearing portals. The eight R1 source documents and the project index are
pinned by SHA-256. Each source document validates against its declared schema under
the reader's own evaluator.

A hundred and four inert edit records each yield exactly one expected code, file and
JSON path, or acceptance for the ten positive records. The defects covered are:

- malformed and ambiguous bytes, out-of-range numbers and excessive nesting;
- future, older and unknown versions and formats;
- duplicate members, objects, catalog entries and fields, tileset IDs, dependencies
  and contracts;
- dangling, wrong-kind, wrong-owner and out-of-closure references, including portals,
  parameterless catalog entries and movement-profile uses;
- missing dependencies and unreachable documents;
- tampered sizes, hashes, digests and manifest order;
- unsupported and undeclared contracts, and contracts bound to the wrong role;
- invalid asset paths: reserved, traversal, media mismatch and unbundled.

The first exact-head review (at `176d764`) was blocked. Parameterless and profile
catalog uses went unchecked, cross-map references were not limited to the dependency
closure, and duplicates outside maps were accepted. The repair added a record for
each finding and for each previously untested code. The second review (at `bda7f55`)
was blocked too: contract refs were checked against one global set rather than per
role, and a profile was resolved only in maps that declared it. The second repair
checks roles, resolves each profile in every map whose closure holds it, aligns
terrain tilesets, absent optional dependencies and group-kind layers with the
library, and adds a record for each.

A differential test compares the reader's parser and schema evaluator with
`src/contracts` on every owned conformance file and R1 example. It exposed an
off-by-one nesting-depth limit, now aligned to 64 containers. Clean-install,
canonical and security results and the independent exact-head review are captured
in the PR and the external ledger.
