# [ML-007] [FEATURE] Add independent final-byte fixture reader

## Change

Record ML-006's verified protected squash and successful main CI, retire it to
history and promote ML-007. Preserve ML-008–044 exactly. Add `consumer/`, an
independent bundle reader that runs as its own Node process. It reads final
export bytes and the pinned published schemas from disk and imports only Node
built-ins: never `src/`, the editor, React or a bundler. Pin the R1 forest source
documents and export bundle as golden inputs with declared schemas in
`conformance/bundle/`, plus inert mutation records for the negative suite.

## Reason

The adopted G1 load sequence and I3 independent-consumer layer require a reader
that parses exported bytes rather than receiving the editor's in-memory objects.
A second implementation of the byte, schema and reference rules also catches
defects that a consumer sharing the editor's own format library would repeat.

## Impact

`node consumer/read-bundle.mjs --schemas DIR BUNDLE` performs G1 steps 1–4 for a
folder bundle and prints a JSON report: bounded safe-path inventory with symlink,
alias and unexpected-entry rejection; duplicate-key-rejecting strict UTF-8 JSON;
complete manifest inventory with exact sizes, SHA-256 and bundle digest; exact
format/version and required-contract negotiation; independent closed-schema
evaluation; and document, dependency, typed-reference, portal, catalog-call and
asset-path resolution. It constructs no world, renderer, engine or navigation.

## Risk

A reader that trusted the editor's objects, accepted `version <= latest`, ignored
duplicate keys or skipped unlisted files would certify bundles a real importer
must refuse. Every rejection class has a negative mutation record that runs in a
separate process. The reader fails closed on any unclassified reference field, so
a later schema change cannot silently bypass reference checks.
